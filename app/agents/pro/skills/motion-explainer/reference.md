# راهنمای کامل تولید موشن‌گرافیک «تاریخ داره تکرار می‌شه»

> **برای Claude Code:** این سند کل خط تولید یک موشن‌گرافیک عمودی فارسی (۱۰۸۰×۱۹۲۰، ۳۰fps، ~۹۴ ثانیه) را شرح می‌دهد: از تحلیل ویدیوی مرجع تا صدا، زمان‌بندی، صحنه‌ها، صدای پس‌زمینه و رندر نهایی.
> پیاده‌سازی مرجع با **Remotion (React + SVG)** ساخته شده. سورس کامل در `motion_source.zip` کنار همین فایل هست. هدف این سند این است که بتوانی همین را در یک ادیتور دیگر بازسازی کنی. بخش ۱۱ نحوه‌ی نگاشت مفاهیم به یک ادیتور تایم‌لاین‌محور را توضیح می‌دهد.

---

## ۰. نمای کلی خط تولید

```
ویدیوی مرجع ──► ① تحلیل (فریم + صدا + ویسپر)
                     │
                     ▼
               ② متن نریشن (lines.json ـ ۱۳ جمله)
                     │
                     ▼
               ③ TTS جمله‌به‌جمله با ElevenLabs + زمان‌بندی حرف‌به‌حرف
                     │
                     ▼
               ④ پردازش صدا (atempo 1.12) ──► ⑤ timing.json (شروع/مدت هر صحنه + alignment)
                                                      │
                     ┌────────────────────────────────┤
                     ▼                                ▼
               ⑥⑦⑧ صحنه‌ها (کامپوننت + cue)         ⑨ میکس صدا (نریشن + موزیک سنتزی + ووش + داکینگ)
                     │                                │
                     ▼                                ▼
               ⑩ رندر ویدیو بی‌صدا ───────────► mux نهایی ──► motion_fa.mp4
```

**اصل کلیدی معماری:** همه‌چیز **داده‌محور** است. صدا اول ساخته می‌شود و زمان‌بندی تصویر از روی صدا درمی‌آید، نه برعکس. هر انیمیشن داخل صحنه به یک **کلمه‌ی نریشن** وصل است (`cue('کلمه')`)، نه به یک عدد ثابت. پس اگر صدا عوض شود، کل ویدیو خودبه‌خود دوباره هماهنگ می‌شود.

## ۱. تحلیل ویدیوی مرجع

### ۱.۱ مشخصات
```bash
ffprobe -v error -show_entries format=duration:stream=codec_type,width,height,r_frame_rate -of compact ref.mp4
# نتیجه: 1080x1920، 30fps، 78.4 ثانیه، صدا = نریشن پیوسته + موزیک
```

### ۱.۲ برگه‌ی فریم‌ها (contact sheet) برای فهم سبک و ساختار
```bash
ffmpeg -i ref.mp4 -vf "fps=1/2,scale=360:-1" frames/f_%03d.jpg
ffmpeg -pattern_type glob -i 'frames/*.jpg' -vf "tile=8x5" contact.jpg
```
از روی این برگه سبک بصری (بخش ۶) و ترتیب صحنه‌ها (بخش ۷) درآمد. متن‌های روی صفحه هم کمک کردند متن نریشن بازسازی شود.

### ۱.۳ استخراج صدا و پیاده‌سازی متن
```bash
ffmpeg -i ref.mp4 -vn -ac 1 -ar 16000 audio.wav
```
ترنسکرایب با **Whisper medium** (نسخه‌ی ONNX از sherpa-onnx) + **Silero VAD** برای تکه‌کردن صدا به جمله‌ها:
```python
import sherpa_onnx as so, soundfile as sf
rec = so.OfflineRecognizer.from_whisper(encoder=".../medium-encoder.int8.onnx",
        decoder=".../medium-decoder.int8.onnx", tokens=".../medium-tokens.txt",
        language="fa", task="transcribe")
# VAD: min_silence_duration=0.15, min_speech_duration=0.2, max_speech_duration=12
# هر تکه‌ی VAD جداگانه decode می‌شود → [start-end] text
```
> **نکته:** وقتی موزیک پشت صداست، ویسپر بعضی تکه‌ها را نیمه‌کاره برمی‌گرداند. متن نهایی از **ترکیب خروجی ویسپر + متن‌های روی صفحه** بازسازی شد. اگر ویسپر محلی (`openai-whisper` یا `whisper.cpp`) داری، همان کافی است.

**قواعد نوشتن متن برای TTS فارسی:**
- **نیم‌فاصله (ZWNJ, `U+200C`)** در «می‌شه»، «مرحله‌ی»، «کسب‌وکار». بدون آن، TTS کلمه را بد می‌خواند و جست‌وجوی cue هم خراب می‌شود.
- **کسره‌ی اضافه** (`ِ`) جایی که ممکن است خوانده نشود، مثل «سالِ نود و پنج» و «پولِ اصلی».
- **عددها با حروف** («نود و پنج»، «دو») تا تلفظ قطعی باشد. روی صفحه با رقم فارسی (۹۵، ۲) نمایش داده می‌شوند.
- **ویرگول = مکث کوتاه**، **`...` = مکث دراماتیک**.
- متن روی صفحه لازم نیست عیناً همان نریشن باشد. خلاصه‌شده‌اش هم کار می‌کند (بخش ۷).

## ۳. تولید صدا با ElevenLabs (جمله‌به‌جمله + timestamps)

**چرا جمله‌به‌جمله؟** مدت دقیق هر صحنه مستقیم از طول فایل صوتی همان جمله درمی‌آید و هر جمله را می‌شود جدا دوباره ساخت.

**endpoint:** `POST https://api.elevenlabs.io/v1/text-to-speech/{voice_id}/with-timestamps?output_format=mp3_44100_128`

```python
body = {
  "text": text,
  "model_id": "eleven_v3",          # v3 فارسی را ساپورت می‌کند (multilingual_v2 / flash نه)
  "language_code": "fa",
  "voice_settings": {"stability": 0.5, "similarity_boost": 0.8}
}
headers = {"xi-api-key": KEY, "Content-Type": "application/json"}
# پاسخ: {"audio_base64": "...", "alignment": {"characters": [...],
#        "character_start_times_seconds": [...], "character_end_times_seconds": [...]}}
```
- voice_id استفاده‌شده: `wEMHmIPIdyXK6OkgkB03` (صدای کلون‌شده‌ی خودت با نام «صدای من»).
- خروجی: `voice/NN.mp3` + `voice/NN.json` (همان آبجکت `alignment`).
- اسکریپت کامل: `make_voice.py` (توی پوشه هست). جمله‌هایی که از قبل ساخته شده‌اند را رد می‌کند.

**دام‌ها:**
- `mp3_44100_192` فقط از پلن Creator به بالا مجاز است و روی پلن پایین‌تر خطای 403 می‌دهد. از `mp3_44100_128` استفاده کن.
- اگر درخواست وسط کار شکست بخورد، فایل را **بعد** از دریافت موفق باز کن، نه قبلش. وگرنه یک mp3 صفربایتی می‌ماند که دفعه‌ی بعد «skip» می‌شود.
- آرایه‌ی `characters` دقیقاً با متن ارسالی یکی است (با ZWNJ و کسره). پس `indexOf` روی متن اصلی همان ایندکس alignment را می‌دهد.

## ۵. مدل زمان‌بندی — `timing.json`

اسکریپت `build_timing.py` این فایل را می‌سازد:
```python
LEAD = 0.25   # سکوت اول ویدیو
GAP  = 0.22   # فاصله‌ی بین دو جمله
TAIL = 2.6    # ادامه‌ی ویدیو بعد از آخرین جمله (برای انیمیشن «ارسال شد»)
t = LEAD
for id, text in lines:
    dur = ffprobe(proc/id.wav)
    scenes.append({id, text, start: t, dur, audio: True,
                   al: {chars: "".join(characters), starts: scaled_starts}})
    t += dur + GAP
total = t + TAIL
```

### ۵.۱ تابع `cue` (قلب هماهنگی صدا و تصویر)
```ts
// زمان شروع یک کلمه در صدا، نسبت به شروع صحنه (ثانیه)
const makeCue = (text, dur, al) => (s, occ = 0, offset = 0) => {
  const src = al ? al.chars : text;
  let idx = -1, from = 0;
  for (let i = 0; i <= occ; i++) { idx = src.indexOf(s, from); if (idx < 0) break; from = idx + 1; }
  if (idx < 0) return offset;                       // پیدا نشد → اول صحنه
  if (al) return al.starts[idx] + offset;           // دقیق از alignment
  return (idx / src.length) * dur + offset;         // fallback: تخمین خطی
};
```
- `occ` = چندمین تکرار کلمه (مثلاً «مرحله» چند بار در یک جمله هست).
- `offset` معمولاً **۰.۱- تا ۰.۲-** است. نوشته کمی **قبل** از گفته‌شدن کلمه ظاهر می‌شود و حس snappy می‌دهد.

### ۵.۲ پنجره‌ی نمایش هر صحنه
```
visibleFrom = start - 0.05           (صحنه‌ی اول از 0)
visibleTo   = nextScene.start + 0.12 (صحنه‌ی آخر تا total)
```
همپوشانی کوتاه با صحنه‌ی بعد باعث می‌شود خروجِ این صحنه و ورودِ صحنه‌ی بعد روی هم بیفتند (cross-transition).

### ۶.۳ فونت
**Vazirmatn** با وزن‌های 400/500/700/800/900 (از `@fontsource/vazirmatn`).
- تیتر بزرگ: 900، اندازه‌ی 110 تا 190px، `letterSpacing: -2`، `lineHeight: 1.12`
- زیرتیتر: 500، اندازه‌ی 52 تا 60px، رنگ MUTED
- پیل: 700، اندازه‌ی 38 تا 52px
- رقم‌ها همیشه فارسی: `fa = n => String(n).replace(/[0-9]/g, d => '۰۱۲۳۴۵۶۷۸۹'[d])`
- **مهم:** قبل از رندر صبر کن تا فونت لود شود (`document.fonts.load('900 40px Vazirmatn','سلام')`). وگرنه فریم‌های اول با فونت پیش‌فرض رندر می‌شوند.

### ۶.۴ پس‌زمینه (لایه‌ی ثابت زیر همه‌ی صحنه‌ها)
1. گرادیان شعاعی بالا
2. **گرید نقطه‌چین:** خطوط عمودی هر 90px (افست 45-)، افقی هر 90px، `stroke #9aa199`، `strokeWidth 1.6`، `dasharray "6 9"`، و نقطه‌ی r=3 روی هر تقاطع. کل گرید با یک **ماسک بیضی نرم** (rx=430، ry=520) فقط وسط کادر دیده می‌شود. مرکز ماسک آرام حرکت می‌کند:
   `cx = 540 + sin(t*0.3)*60`، `cy = 1150 + cos(t*0.25)*80`. opacity کل گرید = 0.55
3. ویگنت: `box-shadow: inset 0 0 260px rgba(0,0,0,0.10)`

### ۶.۵ منحنی‌ها و حرکت
- **easeOut اصلی:** `cubic-bezier(0.16, 1, 0.3, 1)`
- **easeInOut:** `cubic-bezier(0.65, 0, 0.35, 1)` (برای پر شدن نمودار، باز شدن پنجره، پرواز)
- **spring:** `stiffness 120`، `damping 12–15`، `mass 0.6–0.9` (برای pop شدن آبجکت‌ها، پیل‌ها و بج‌ها). damping 9 برای pop پرانرژی‌تر (عدد «۲»، حباب‌های خنده)
- `prog(t, at, dur)` = `ease(clamp((t-at)/dur))`، پیشرفت 0 تا 1 از لحظه‌ی `at`

### ۶.۶ کامپوننت‌های پایه (بلوک‌های سازنده)

| کامپوننت | ورود | پارامترها |
|---|---|---|
| **Txt** (متن یک‌خطی) | opacity 0→1، blur 12→0px، translateY 40→0 در 0.55s easeOut | at, size, weight, color |
| **Words** (تیتر کلمه‌به‌کلمه) | هر کلمه با تأخیر 0.12s: opacity، blur 14→0، translateY 60→0، scale 0.85→1 در 0.6s. کلمه‌های لیست `hl` سبز می‌شوند. `nowrap` | text, at, size, stagger, hl[] |

| **Hl** | بخشی از متن پیل با رنگ `GL` | — |
| **Badge** «مرحله‌ی n» | spring scale 0.4→1. حالت عادی: border 3px سبز، متن سبز، پس‌زمینه‌ی سفید 55%. `active`: پس‌زمینه‌ی سبز و متن سفید. `strike`: خط‌خورده و opacity 0.35 | n, at, active, strike |

### ۶.۷ ترنزیشن بین صحنه‌ها (روی کل صحنه)

## ۷. استوری‌بورد صحنه‌به‌صحنه

> مختصات x,y = مرکز المان روی بوم 1080×1920 (مگر اینکه گفته شود left/top). «@کلمه» یعنی `cue('کلمه')`. offset‌ها داخل پرانتز.

### صحنه ۰۱ — «تاریخ داره تکرار می‌شه» (1.9s)
- مرکز (540,960): حلقه‌ی ۹۰۰px با spring، **دائم در حال چرخش** (`rotate = t*70°`)
  - دایره‌ی r=360 نقطه‌چین (`14 22`)، opacity 0.35
  - کمان r=300 از 0° تا حدود 300° با سر فلش (نماد «تکرار»)، stroke 10، opacity 0.6
- تیتر دوخطی، size 170: «تاریخ داره» @0.05 / «تکرار می‌شه» @تکرار(-0.1) با هایلایت «تکرار»

## ۹. صدای نهایی (`music.py`)

### ۹.۱ موسیقی پس‌زمینه (کاملاً سنتزی، بدون فایل خارجی، 48kHz)
- **96 BPM**، آکوردهای **Am – F – C – G** (هر آکورد یک میزان = 2.5s)
- **Pad:** هر نت آکورد = دو سینوس detune‌شده (±0.08%) + هارمونیک 2 و 3. attack 0.6s، release 0.5s، gain 0.035
- **Sub bass:** ریشه‌ی آکورد یک اکتاو پایین، `exp(-t*0.6)`، gain 0.10
- **Pluck:** آرپژ نت‌چنگ با الگوی `[0,2,1,3,2,1,3,2]` یک اکتاو بالاتر، `exp(-t*7)`، gain 0.03 / 0.02
- **Shaker:** نویز high-pass ‏7kHz روی ضرب‌های فرد، decay 60
- fade in یک ثانیه، fade out دو ثانیه، low-pass ‏9kHz

### ۹.۲ افکت ووش
در هر تغییر صحنه (0.35s قبل از start): نویز band-pass ‏400–3500Hz به طول 0.55s با پوش `sin²`، gain 0.05

### ۹.۳ میکس
```
bed  = (music*0.5 + sfx*0.8) * duck
duck = 1 - 0.45 * clip(envelope(voice) / (max*0.25))   # envelope = |voice| low-pass 4Hz
mix  = voice + bed → normalize peak 0.89 → loudnorm I=-14 LUFS, TP=-1
```
نتیجه: گفتار حدود 16- dB RMS، موزیک تنها حدود 26- dB. یعنی موزیک ~۱۰dB زیر صداست و زیر گفتار باز هم پایین‌تر می‌رود.

## ۱۱. پیاده‌سازی در یک ادیتور دیگر (نگاشت مفاهیم)

اگر ادیتور تو تایم‌لاین/لایه/کی‌فریم دارد، این نگاشت را استفاده کن:

| مفهوم در Remotion | معادل در ادیتور |
|---|---|
| `Sequence from/duration` هر صحنه | یک **گروه/کامپوزیشن** روی تایم‌لاین با start و duration از `timing.json` |
| `cue('کلمه', occ, offset)` | **مارکر** روی تایم‌لاین صدا. کی‌فریم‌های ورود المان به مارکر snap می‌شوند. مارکرها از `alignment` ساخته می‌شوند |
| `Txt`/`Words`/`Pill`/`Badge` | **پریست‌های انیمیشن متن** (presets) با پارامترهای بخش ۶.۶ |
| `spring(...)` | easing از نوع spring یا overshoot (`cubic-bezier(0.34,1.56,0.64,1)` تقریب قابل‌قبولی است) |
| `prog(t, at, dur)` + easeOut | دو کی‌فریم (at و at+dur) با `cubic-bezier(0.16,1,0.3,1)` |
| SceneWrap (zoom + خروج blur) | افکت روی گروه صحنه: scale 1→1.035 کل مدت + ترنزیشن خروج 0.28s |
| SVG art | **لایه‌ی وکتور/شیپ** یا SVG import. پارامترهای متحرک (سطح شن، رشد جوانه، باز شدن پنجره) = یک property عددی 0..1 که کی‌فریم می‌خورد |
| حلقه‌های بی‌نهایت (چرخش، اسکرول فید، پالس مدار، شناوری) | **expression** یا property وابسته به زمان (`sin(t)`، `t*speed % L`) |

### فرمت داده‌ی پیشنهادی برای ادیتور (Scene Spec)
