# پرامپت و مشخصات ساخت موتور «کتابخانه‌ی سبک‌ها» در ادیتور جی پی تی

> بر پایه‌ی Lemo-Opuscar (۹۹ سبک فیلم، ۱۵ دسته) + تجربه‌ی ساخت عملی ویدیوی Whiteboard دراپ‌شیپینگ
> این فایل را کامل به Claude Code داخل ادیتور جی پی تی بده. بخش ۱۸ پرامپت اصلی است؛ بقیه‌ی بخش‌ها مشخصاتی است که پرامپت به آن‌ها ارجاع می‌دهد.
> پیوست: `whiteboard_engine_source.zip` (پیاده‌سازی مرجع یک سبک با پایپ‌لاین کامل فارسی)

---

## ۰. خلاصه در یک پاراگراف

می‌خواهیم در ادیتور جی پی تی یک «موتور فیلم سبک‌دار» بسازیم که کاربر بگوید «یک ویدیو درباره‌ی X در سبک Y» و موتور، مثل یک کارگردان، کل مسیر را طی کند: انتخاب سبک → تحقیق → تریتمنت → متن → صدای ElevenLabs → ساخت صحنه‌ها با کد → رندر فریم‌به‌فریم → طراحی صدا و میکس → QA خودکار → تحویل. همه‌ی ۹۹ سبک Lemo-Opuscar در یک **رجیستری سبک** ثبت می‌شوند، هر کدام با «قانون‌نامه‌ی ۱۱ بخشی» و یک «موتور کد» (اغلب همان کد دموی MIT خودشان)، و یک **لایه‌ی فارسی/عمودی** که روی همه اعمال می‌شود.

---

## ۱. هدف و غیرهدف

**هدف**
- پشتیبانی از کل کتابخانه (۹۹ سبک) با یک پایپ‌لاین مشترک.
- فارسی و راست‌به‌چپ کامل، قاب عمودی 1080×1920 و افقی 1920×1080.
- صدای «صدای من» در ElevenLabs، موسیقی و افکت ElevenLabs یا سمپلر Opuscar.
- خروجی قابل‌تکرار: هر فیلم یک پوشه با `build.sh` که با `content.json` جدید دوباره رندر می‌شود (قالب سری‌های هفتگی).
- QA خودکار: خوانایی متن، تطبیق صدا با متن (Scribe)، بلندی −14 LUFS، فریم سیاه.

**غیرهدف**
- تولید ویدیو با هوش مصنوعی یا استاک‌فوتیج به‌جای کد (فقط سبک‌های Edit & Documentary فوتیج واقعی می‌خواهند، آن هم با مجوز).
- کپی داستان، شات یا تایم‌لاین دموها. دمو فقط برای یاد گرفتن تکنیک است.

## ۳. معماری

```
                    ┌────────────────────────── Style Registry ──────────────────────────┐
                    │ 99 × { style.json, STYLE.md|STYLE_OWN.md, STYLE_FA.md, engine/ }    │
                    └───────────────┬─────────────────────────────────────────────────────┘
brief ──► Director (agent loop) ────┤
           │ research, treatment,   │
           │ script, cue map        ▼
           │              film/<slug>/ (پروژه‌ی هر فیلم)
           │                ├─ film.json        ← FilmSpec: سبک، اندازه، fps، صحنه‌ها
           │                ├─ lines.json       ← متن صدا
           ├─► Voice adapter (ElevenLabs TTS + alignment) ─► voice/*.wav + words.json
           ├─► Picture backend:
           │      A) PAGE  : index.html با window.render(t) → Playwright فریم‌به‌فریم   (۹۹ سبک کتابخانه)
           │      B) REMOTION: کامپوننت React → Remotion                                 (موتورهای اختصاصی ما)
           ├─► Sound: SFX از EV/آیتم‌ها + موسیقی (ElevenLabs Music یا sampler) ─► mix.wav
           └─► Master: mux + loudnorm −14 LUFS ─► QA ─► تحویل
```

**تصمیم کلیدی — دو بک‌اند تصویر، یک لایه‌ی مشترک:**
- **PAGE (پیش‌فرض برای کتابخانه):** ۳۷ سبک three.js و حدود ۴۸ سبک WebGL دارند؛ موتور همه‌ی دموها `index.html` با قرارداد `render(t)` است. پس بک‌اند اصلی، همان `core/render` (MIT) است و پورت هر سبک یعنی «استفاده‌ی مجدد از موتور دموی خودش» (مثلاً `styles/whiteboard/demo/engine/wb.js`) + لایه‌ی فارسی.
- **REMOTION:** برای موتورهای اختصاصی ما (Vox، Premium Edit، Ad Reel، Whiteboard نسخه‌ی SVG) که فوتیج واقعی، ویدیوی آلفا و کامپوننت React لازم دارند.
- لایه‌ی مشترک (صدا، تایم‌لاین، زیرنویس، میکس، QA) برای هر دو بک‌اند یکی است. قرارداد اتصال: هر دو بک‌اند `EV` (رویدادهای صدا) و `TEXTS(t)` (متن‌های روی صفحه) را خروجی می‌دهند.

## ۵. قراردادها (Contracts)

### ۵.۱ قرارداد صفحه (بک‌اند PAGE — از Opuscar)

```js
window.DUR = 112.7;                         // ثانیه
window.render = (t) => { ... };             // قطعی؛ بدون Date.now و Math.random بی‌seed؛ بدون state بین فریم‌ها
window.READY = true;                        // بعد از لود همه‌ی فونت‌ها و تصاویر
window.EV = [{t, type, gain?, pan?}];       // رویدادهای صدا
window.TEXTS = (t) => [{id, text, x0,y0,x1,y1, pass?}];   // برای readcheck
```

- رندر: `node core/render/video.mjs <film> --size 1080x1920 --fps 30 --workers N`
- استیل: `node core/render/still.mjs <film> 1.5 12 --range 0:110:4`
- روی سرور بدون GPU: `LEMO_ANGLE=swiftshader` (وگرنه سبک‌های WebGL خالی رندر می‌شوند).
- مسیرها absolute (`/core/lib.js`)، هرگز `../..`.

### ۵.۲ FilmSpec (`film.json`)

```json
{
  "slug": "dropshipping-whiteboard",
  "style": "whiteboard",
  "backend": "page",
  "size": [1080, 1920], "fps": 30,
  "lang": "fa", "voice_id": "<از config>",
  "tempo": 1.2, "scene_gap": 0.45, "tail": 2.6,
  "cta": {"text": "کلمه‌ی «شروع» رو کامنت کن", "offer": "آموزش رایگان مزه بدون مرز"},
  "brand": {"accent": "#2a5cb3", "fonts": {"title": "Marhey", "caption": "Doran"}},
  "scenes": [
    {"id": "01", "region": "header", "intent": "hook", "line": "متن صدای صحنه", "visual_beats": [
      {"on_word": "انبار", "do": "draw warehouse + red X"}
    ]}
  ]
}
```

### ۵.۳ زمان‌بندی

- `data.json` (تولیدشده): `scenes[{id,start,dur,words[{t,s,e}],split?}]`، `total`.
- هر انیمیشن به **کلمه‌ی گوینده** قفل می‌شود: `c(scene, word, occ, off)` → زمان مطلق. هیچ زمان دستی ثابت در کد صحنه نیست.
- `split`: مکث عمدی وسط یک خط (مثلاً نگه داشتن نمای کل تخته). کلمات بعد از نقطه‌ی split جابه‌جا می‌شوند و صدا در میکس دو تکه پخش می‌شود.

`build_registry.py` از `vendor/.../styles/*/style.json` و STYLE.md ها این را می‌سازد:

```json
  "category": "Sketch & Board", "category_fa": "اسکچ و تخته",
  "uses": ["Science explainers"], "needs": [],
  "engine": "canvas2d | three | webgl | footage | image-gen",
  "demo_engine_files": ["demo/engine/wb.js"],
  "native_fps": 24, "default_size": [1920,1080],
  "vertical_ready": false,
  "fa_status": "none | draft | verified",
  "sound_palette": "...", "native_moves": ["..."],
  "poster": "styles/whiteboard/poster.jpg"

```

- `engine` را خودکار تشخیص بده: وجود `three` در index.html → three؛ `getContext('webgl` → webgl؛ STYLE.md که از footage/ffmpeg حرف می‌زند → footage؛ `needs: image-generation` → image-gen؛ بقیه canvas2d.
- نام و دسته‌ی فارسی را خودت ترجمه کن (فهرست کامل ۹۹ سبک در `AGENTS.md` بین `style-list:start/end`).
- **STYLE_FA** (`registry/fa/<slug>.md`) برای هر سبک فقط این‌ها را بازنویسی می‌کند و بقیه‌ی STYLE.md دست‌نخورده می‌ماند:
  1. §4 تایپ و زیرنویس: معادل فونت فارسی هم‌جنس (سریف/سنس/دست‌نویس/ضخیم)، جهت، اندازه، حرکت ورود کلمه‌به‌کلمه.
  2. کادر عمودی: نسبت و safe zone، چیدمان دوباره‌ی HUD و عنوان‌ها.
  3. نرخ خواندن و طول نگه‌داشت.
  4. هر pitfall جدیدی که فارسی می‌آورد.

## ۸. آداپتور صدا (ElevenLabs) — همان چیزی که در عمل جواب داد

**تولید (`tts_elevenlabs.py`)**
- `POST /v1/text-to-speech/{voice_id}/with-timestamps?output_format=mp3_44100_128`، بدنه `{"text", "model_id": "eleven_v3"}`.
- خروجی هر خط: `<id>.mp3` + `<id>.al.json` (alignment کاراکتری).
- کلید از `ELEVENLABS_API_KEY` یا فایل محلی کاربر؛ **هرگز چاپ، لاگ یا کامیت نشود**.
- هر خط جدا تولید شود تا بازتولید یک خط ارزان باشد. درخواست‌ها حداکثر ۶ تا در هر اجرا (محدودیت زمان و نرخ API). روی `429 system_busy` چند ثانیه صبر کن و دوباره بفرست.

**پردازش (`proc_voice.py`)**
1. تبدیل به 48kHz mono → `silencedetect=n=-40dB:d=0.18`.
2. سکوت‌های داخلی به ۰.۱۶ ثانیه کوتاه شوند، ابتدا و انتهای خط trim، fade شش میلی‌ثانیه‌ای در هر برش.
3. `atempo=1.2` (صدای v3 برای این صدا آرام است؛ بالاتر از 1.25 برای فارسی عجول می‌شود) + `highpass 70Hz` + compressor ملایم.
4. **نگاشت زمان کلمات**: alignment روی صدای خام است. برای هر زمان خام t: `t_proc = (مجموع طول بخش‌های نگه‌داشته‌شده قبل از t + فاصله‌ی t از شروع بخش جاری) / tempo`. کلمات از کاراکترها با شکستن روی فاصله ساخته می‌شوند. نیم‌فاصله (ZWNJ) جداکننده نیست.

**QA (`asr_scribe.py`)**
- `POST /v1/speech-to-text`، `model_id=scribe_v1`، `language_code=fas`، روی **میکس نهایی** و هر خط جدا.
- نرمال‌سازی قبل از مقایسه: ی/ي، ک/ك، حذف اعراب و نیم‌فاصله، اعداد فارسی/لاتین/حروفی، حذف علائم.
- آستانه‌ی شباهت ۰.۹۰. خطاهای شناخته‌شده‌ی خودِ Scribe (مثل «نیچ» که «نیش» نوشته می‌شود، یا نام‌های لاتین مثل Drop Ship) در فیلد `asr` همان خط ثبت شوند.

## ۹. لایه‌ی فارسی/RTL

**Canvas (بک‌اند PAGE) — `fa/rtl.js`**
- `ctx.direction='rtl'`، `textAlign='right'`، شکستن خط با `measureText`.
- **جلوه‌های حرف‌به‌حرف ممنوع**: حروف فارسی به هم متصل‌اند و جدا کشیدن‌شان شکل اتصال را می‌شکند. جایگزین‌ها:
  - **کلمه‌به‌کلمه** برای pop، stagger و typewriter.
  - **wipe راست‌به‌چپ با clip** برای «نوشته شدن» (whiteboard، marker، chalk، one-line). قلم یا ماژیک روی لبه‌ی wipe حرکت کند، با کمی نوسان عمودی دور خط کرسی.
- اعداد: در متن صدا با حروف، روی صفحه با ارقام فارسی (`toFaDigits`). در فونت‌هایی که ارقام عربی دارند (مثل Marhey که ۴ و ۵ و ۶ را عربی می‌کشد) عدد را با فونت دیگری (Doran یا Vazirmatn) بنویس.
- گیومه «» و علامت ٪: اول ببین فونت گلیفش را دارد، وگرنه حذف یا جایگزین کن.

**SVG/Remotion — `fa/rtl.tsx`**
- `<text direction="rtl">` با `textAnchor="middle"` و مرکزی که از عرض اندازه‌گیری‌شده حساب شده. برای چسباندن به لبه‌ی راست، `textAnchor="start"` همراه `direction="rtl"` لبه‌ی راست را روی x می‌گذارد (`end` اشتباه است و متن از قاب بیرون می‌زند).
- **باگ مهمی که دیدیم:** اندازه‌گیری عرض متن قبل از لود فونت عدد غلط می‌دهد. کش اندازه‌گیری فقط بعد از `document.fonts.load(...)` و `fontsReady=true` پر شود.

**خوانایی — `readcheck_fa.mjs`**
- حداقل نگه‌داشت = حروف فارسی ÷ ۱۳ + بقیه ÷ ۱۵ + ۱.۵ ثانیه (حداقل ۱.۸).
- زیرنویس: حداکثر ۲۶ کاراکتر یا ۵ کلمه در هر تکه، شکستن روی علائم، فونت Doran Bold حدود ۵۰px.

**قاب عمودی 1080×1920**
- ناحیه‌ی امن محتوا: y از ۱۰۰ تا ۱۴۵۰. زیرنویس حدود y=۱۴۹۰ تا ۱۶۲۰. پایین ۳۰۰px برای رابط کاربری اینستاگرام خالی بماند.
- سبک‌های افقی ذاتی (تخته‌ی بزرگ، نقشه، خط زمان) با «دوربین روی بوم بزرگ» عمودی می‌شوند، نه با کوچک کردن کل کادر.

## ۱۱. صدا و موسیقی

- **SFX:** برای هر سبک، از «sound palette» در STYLE.md یک فهرست ۶ تا ۱۰ صدایی بساز و با `POST /v1/sound-generation` (`duration_seconds`، `prompt_influence=0.6`) تولید و در `sfx/<style>/` کش کن. نمونه‌ی وایت‌برد: ماژیک سریع، خط بلند، جیغ ماژیک، درپوش، whoosh، pop، دینگ، آهنربا، تیک.
- **foley خودکار:** هر آیتمی که قلم دارد یک برش تصادفی از صدای ماژیک به طول خودش می‌گیرد (fade سی میلی‌ثانیه‌ای، pan تصادفی ±۰.۳۵). روی خط‌های بلند گاهی جیغ ماژیک اضافه شود. رویدادهای `EV` صدای خودشان را دارند.
- **موسیقی:** `POST /v1/music` با `force_instrumental: true` و `music_length_ms` برابر طول فیلم + ۱۰ ثانیه، و پرامپتی از سازهای sound palette (نه «پیانو و زهی» عمومی)، یا اسکور سمپلری Opuscar (`core/audio/sampler.py`).
- **میکس:**
  - صدای گوینده peak 0.85.
  - موسیقی حدود −17dB پایه، و زیر صدا تا ۵۵٪ پایین‌تر (attack ۶۰ و release ۴۰۰ میلی‌ثانیه).
  - SFX حدود ۰.۵۵.
  - fade-in موسیقی ۰.۶ و fade-out ۲.۸ ثانیه.
  - loudnorm دومرحله‌ای به I=−14 و TP=−1.5، بعد limiter.
- میکس با numpy راحت‌تر و پایدارتر از filtergraph ffmpeg با صدها ورودی است.

## ۱۵. درس‌هایی که در ساخت عملی گرفتیم (حتماً رعایت شود)

1. **Remotion v4:** گزینه‌ی خروجی `renderMedia` اسمش `outputLocation` است، نه `output`. با `output` رندر «done» چاپ می‌کند اما هیچ فایلی نمی‌نویسد. یک بار به همین دلیل یک رندر ۱۵ دقیقه‌ای از دست رفت.
2. `concurrency` باید ≤ تعداد هسته‌ها باشد. روی سرور ۲ هسته‌ای، ۱۱۳ ثانیه 1080×1920 حدود ۱۵ دقیقه طول کشید. همیشه اول یک رندر ۱۰ فریمی تست کن.
3. فونت‌ها قبل از اولین اندازه‌گیری لود شوند (`delayRender` + `document.fonts.load`). کش عرض متن فقط بعد از آن.
4. `roughjs` برای حس دست‌کشیده عالی است: `disableMultiStroke: true`، `roughness≈0.9`، seed ثابت برای قطعی بودن.
5. draw-on مسیر با `strokeDasharray = len` و `strokeDashoffset = len×(1−p)`. طول با `@remotion/paths` (`getLength` و `getPointAtLength`)، که نوک قلم را هم دقیق می‌دهد.
6. منحنی سرعت دست: `u − sin(2πu)/(2π)×0.8`. قلم بین دو آیتم با فاصله‌ی کمتر از ۱.۳ ثانیه با lift و سایه می‌پرد؛ اگر فاصله بیشتر باشد بیرون کادر پارک می‌کند.
7. دوربین: درون‌یابی zoom در فضای 1/z، و فرورفتگی zoom (×۰.۷۴) وسط هر جابه‌جایی. «نمای کل بوم» در پایان، شات امضاست.
8. رنگ جوهر با `mixBlendMode: multiply` و opacity حدود ۰.۹۴. پاک‌کن با mask روی آیتم‌ها و یک «شبح» با opacity حدود ۰.۰۹ که باقی می‌ماند.
9. هر عدد یا متن روی بورد باید از کلمه‌ی گوینده زمان بگیرد. وقتی نوشتن یک متن به حرکت دوربین بعدی برسد نیمه‌کاره دیده می‌شود: آن را کوتاه کن یا جابه‌جا کن.
10. اسکریپت صحنه‌ها را با esbuild برای Node هم bundle کن تا میکسر پایتون زمان آیتم‌ها را از همان منبع بخواند (`timeline.json`) و صدا و تصویر هیچ‌وقت از هم جدا نشوند.
11. ElevenLabs Music گاهی `429 system_busy` می‌دهد؛ چند ثانیه بعد دوباره بفرست. SFX و TTS پایدار بودند.
